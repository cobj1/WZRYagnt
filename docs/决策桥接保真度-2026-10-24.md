## 1. 修的是什么

离线评估报告 §2 已经指出：`data/matches/*/states.jsonl` 里 **`clock_s` / `game_time_s` / `self_state` / `units.pos_minimap` 全部 0/11043**。桥接器虽然不报错，但走了最差的回退分支：

| 字段 | 改造前行为 | 后果 |
|---|---|---|
| 对局时间 | `_game_time()` 恒返回 **0.0** | 每帧都被当成"第 0 分钟"；`time_norm` 是价值模型里符号最稳定的特征（权重 −0.119、符号一致率 0.96），等于**把最强特征钳死** |
| 自身状态 | `self_state` 缺失 → `_hp_ratio()` 恒返回 **1.0** | 模型永远以为满血，"残血该不该打"这类判断完全失效；而 `ui.hp` 在语料里覆盖 58% |

改造后：

1. `_game_time()` 补保真回退链：`clock_s` → `game_time_s` → `ui.match_clock` → `extra.{game_time_s,clock_s,session_elapsed_s}` → `session_elapsed_s` → **`t − session_start_t`** → 0。
2. 新增 `_self_state()`：缺失时用 `ui.hp` 合成（**只补 hp，不伪造金币/装备**，并打 `synthesized=True`）。
3. 回放器新增 `--no-inject-clock` 开关（默认注入 `session_start_t`），用来做前后对照；不影响生产主链路。

**没有改动的东西**：规则 `optimizer`、主循环、`--hok-shadow` 的开关语义、动作流。改动只在 shadow 决策的输入侧。

## 3. 怎么解释

- **目标一致率大涨、类型一致率微降**，方向是对的：模型原先因为 `time_norm=0` 无法区分"开局该占线"和"12 分钟该逼龙"，宏观动作趋于同质；补上时间后它开始输出更多与规则目标重合的宏观动作（推进/后撤/拿资源），代价是偶尔与规则的粗粒度类别不同（例如规则 `skill` vs 模型 `attack_enemy` 都算 engage，但规则的 `combo` 可能对到模型的 `defend_tower`）。
- **游走段收益最大**（+5.3pp）：这正是最依赖"当前是第几分钟"的场景。
- **团战/清线完全没变**：这两类帧的决策主要由局部敌我数量与位置驱动，对时间不敏感，符合预期（也说明改动没有溢出的副作用）。
- **死亡/黑屏略降**（1.25% → 0.75%，405 帧）：该桶里规则基本在等复活，模型开始给"复活后去哪"，反而与规则不一致。样本少，暂不调整。

## 4. 仍然缺的东西（决定了天花板）

即使修好这两个字段，**严格 @3 也只有 11.6%**。剩下的大头：

1. `units.pos_minimap` 仍为 0/11043 —— 屏内单位坐标靠 `minimap.dots` 近似，位置精度到不了"目标点"级别，这是"目标对不上"的第一位原因。
2. `scoreboard`（双方经济/击杀）缺失 → `_gold_by_side()` 只有 self 侧金币，`economy_diff` 类特征在桥上永远是 0。
3. 塔血 `tower_hp` 全部写 1.0（`build_search_state` 里硬编码），等于假设所有塔满血。

**结论**：`hok_bridge` 现在的瓶颈不是算法，是**输入记录器缺字段**。下一步应该改采集器（把 `clock_s`、`pos_minimap`、`scoreboard`、塔血写进 states.jsonl），而不是继续在桥接层做近似——桥接层的近似已经用完了。
