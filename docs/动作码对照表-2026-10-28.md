## 一、来源

`libGameCore.so` 里有一个**标签串 → 动作码**的转换函数，入口 `0x4a4a6b0`：

```
0x4a4a6b0  stp x30, x23, [sp, #-0x30]!
0x4a4a6e4  sub  x8, x8, #7          ; x8 = 标签串长度
0x4a4a6e8  cmp  x8, #9
0x4a4a6ec  b.hi #<拒绝>             ; 只接受长度 7..16
...
0x4a4a730  adrp x1, #0x11d7000
0x4a4a738  add  x1, x1, #0xdca       ; "AtkNorm"
0x4a4a740  bl   #0x4b400d0          ; strncmp(s, label, min(len, 7))
0x4a4a744  cbnz w0, <next>
0x4a4a748  cmp  x21, #6
0x4a4a74c  b.ls <next>
0x4a4a750  mov  w8, #1              ; ← 动作码 1
0x4a4a754  b    #0x4a4aac0
...
0x4a4aac0  str  w8, [x20, #0x1c]    ; 公共出口：码写回结构体
```

**为什么按长度分派**：入口先把长度减 7、与 9 比较，只接受 7–16 字符；组内按长度递增
做前缀 `strncmp`，长度相同才用完整 `strcmp`。这样 `AtkSkill1`（9）不会被 `AtkSkill1x` 误配。

抽取工具：`reverse/dump_action_codes.py` → `reverse/out/diag/action_codes.tsv`。

## 三、由码表纠正的两个结论

1. **#11 `wait_resurrection_armor` 的动作是 `AtkSoldierSkill3`（16）**，
   即「用技能槽 3 打小兵」——与"有复活甲时留在线上刷兵等生效"的语义吻合。
2. **#3 `tactics_UseMapSpecialSkill` 写的 3 不是动作码**。`str w8, [x19, #0xb50]` 的
   `x19 = x0` 是 self/上下文，不是结果结构体；该字段随后被 #11 读进 `result+0xa60`。
   规则的动作码字段只有 `result+0x150`。**上一轮的"动作码 3"已作废。**

## 四、我们这边多出的 11 个标签（已知缺口，非 bug）

`actions.py::_label()` 能为任意 (目标类型, 技能槽) 组合拼出标签，但官方枚举不区分两种情况：

| 情况 | 我们能产出 | 官方等价 |
|---|---|---|
| 技能槽 4 只有通用 | `AtkHeroSkill4` / `AtkSoldierSkill4` / `AtkTowerSkill4` / `AtkCrystalSkill4` / `AtkMonsterSkill4` | `AtkSkill4`（18） |
| 水晶/野怪/无目标不细分技能槽 | `AtkCrystalSkill1..3` / `AtkMonsterSkill1..3` | `AtkSkill1..3` |

合计 **11 个**。`action_codes.collapse()` 给出折叠规则，`test_action_codes.py` 的 T7
把"我们产出的标签必须官方或可折叠"钉住，同时把缺口数量打印出来。

**未改 `enumerate_actions` 的行为**：改动会改变候选集与决策 digest（基线 `90c1a9af`），
按仓库纪律需要真机 A/B 证明"行为等价或更优"才允许接管。此处只提供映射与折叠函数，
是否折叠候选集留给后续单独立项。
