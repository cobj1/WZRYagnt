# 反汇编地址口径勘误（2026-10-28）

> 结论先行：**`RULES_TRIAGE` 表内 52 条地址是正确的 VA，且 100% 精确落在函数序言上。**
> 2026-10-28 早些时候"多数槽位地址落在函数中段、需先做函数边界重建"的结论，
> 是**工具读偏 0x1000 造成的假象**，已作废。C 组 16 条不需要"边界重建"就能读。

---

## 一、根因

`libGameCore.so` 的 `.text` 段 VA 与文件偏移**相差 0x1000**：

| 段 | VA | 文件偏移 | 差 |
|---|---|---|---|
| `.text` | `0x2185770` | `0x2184770` | −0x1000 |
| `.rodata` | `0xfbe3a0` | `0xfbe3a0` | 0 |
| `.plt` | `0x4b3f910` | `0x4b3e910` | −0x1000 |

三个反汇编工具对这件事的处理**不一致**：

| 工具 | 地址换算 | 状态 |
|---|---|---|
| `reverse/rule_consts.py` | `_va_to_off()` 走 PT_LOAD | ✅ 正确 |
| `reverse/func_dump.py` | `text["off"] + (start - text["addr"])` | ✅ 正确 |
| `reverse/disasm_one.py` | `data[addr:]`（VA 直接当文件偏移） | ❌ **读偏 0x1000 = 256 条指令** |

`func_dump.py` 另有一个**入口集缺陷**：它把「所有 `bl` 目标」当函数入口集，
而 RuleTactics 的规则函数是**通过函数指针表调用**的，从不经 `bl`。
实测 52 条地址**命中 `bl` 入口集 0/52**，于是全部回退到 `vaddr - 0x800` 窗口，
输出窗口起点必然早于真实入口 → 系统性制造"目标在函数中段"的观感。

## 二、证据（`reverse/verify_addr_convention.py`）

三条互不依赖的判据：

| 判据 | 结果 | 含义 |
|---|---|---|
| E1 精确命中 `bl` 调用目标 | **0/52 (0.0%)** | 规则经函数指针表调用，`bl` 入口集抓不到 |
| E2 VA 映射下首条即函数序言 | **52/52 (100.0%)** | 表内地址**就是函数入口** |
| E3 地址当文件偏移时首条即序言 | **1/52 (1.9%)** | 读偏 0x1000 后落在函数中段 |

序言判据覆盖编译产物实际出现的全部形态（首条指令做栈分配）：
`stp x29,x30,[sp,#-N]!` / `stp x30,x19,[sp,#-N]!` / `str x30,[sp,#-N]!` /
`str d8,[sp,#-N]!` / `sub sp,sp,#N`，可带 `bti c` / `pacibsp` 前缀。

复现：

```bash
python reverse/verify_addr_convention.py --json reverse/out/diag/addr_convention.json
```

## 三、被推翻的具体结论

`docs/RULES_TRIAGE.md` 的「2026-10-28 函数边界复核（C 组）」整段基于错位字节，逐条作废：

| # | 原结论（错位字节） | 正确反汇编下的实际语义 |
|---|---|---|
| 11 | "101 指令窗口末尾 `b` 回跳，引用串是 `grid_id: %d`/`Damage::InitFeature()`" | 函数入口 `sub sp,sp,#0x40`；引用串 `rule_wait_resurrection_armor`；真实判据见 §四 |
| 3 | "引用串 `ks`/`ay`/`config_file`/`aiPlayer`，无法确认" | 函数入口 `sub sp,sp,#0xe0`；是**多分支调度器**，日志串 `rule_tactics_UseMapSpecialSkill` / `rule_tactics_UseMapSpecialEquiptSkill`，动作码写 `3` |
| 22 | "160 指令含容器遍历与多重状态，无简单阈值" | 函数入口 `str x30,[sp,#-0x60]!`；config `900251`、区间 `[300,301]`、时间差 `≥31`，判据相当具体 |

## 四、重读后的三条真实语义（`evidence=disasm` 成立）

### #11 `wait_resurrection_armor @0x27eb7d8`

```
[x0+0x152c] == 1                        否则 return 0
虚拟调用 [0x517f000+0x2d8](self+0x134, ctx, 0, 0, 0x3c, 1)  → 非 0 直接 return
虚拟调用 [0x517f000+0x418](self+0x134, ctx, &out)            → (w0, out)
要求 w0==1 且 out != 0
遍历 out+0x130 的容器（stride 56 字节，除以 7 的魔数 0x6db6db6db6db6db7）
  元素 +0x00 == 913471 (0xDF03F) 且 元素 +0x58 == 0
  且 self+0x900 的 hp/hp_max > 0.5
  且 s0 < 120.0（s0 为传入浮点）
  → result+0x150 = 16（动作码），result+0xa60 = [self+0xb50]，return 1
```

要点：**动作码 16**；装备/技能 config **913471**；血量门槛 **0.5**；浮点门槛 **120.0**；
容器元素 stride **56**。

### #3 `tactics_UseMapSpecialSkill @0x27d7ce8`

多分支调度器，每个分支结构相同：`状态字段 ≥ 1` + `虚拟谓词为真` → 写动作码 **3** 并 return 1。
已知三个分支的状态字段：`+0x14dc`（UseMapSpecialSkill）、`+0x14e0`（UseMapSpecialEquiptSkill）、
`+0x1490`（第三个，日志串未在本窗口内）。

### #22 `multi_person_cake @0x27fe7c4`

```
[self+0x900]+0x58 >= 1
虚拟调用 [0x517f000+0xfc8](self+0x134, self+0x900, config=900251) → 非空
两次虚拟调用 [0x517f000+0x388](..., &0x542c000+0x5b0 / +0x5bc) → 要求返回值 ∈ [300, 301]
[ctx] - [self+0x1d90] >= 31   （时间差门槛 31）
```

要点：config **900251**、返回值区间 **[300,301]**、时间差 **≥31**。

## 五、剩下真正的阻塞（比"边界重建"更精确）

1. **虚拟调用无法解析**：三条规则的核心判据都是 `adrp x8, <GOT>; ldr x8,[x8,#slot]; blr x8`，
   即通过全局函数指针表间接调用。要知道谓词语义，必须先做 **GOT 槽位 → 方法名** 的解析
   （IL2CPP 的 `Il2CppMethod` 结构或 global-metadata 交叉引用）。这是当前唯一的技术缺口。
2. **官方动作码未映射**：官方内部动作码（16 / 3）与我们 `official_ai/actions.py` 的
   label 体系（`AtkHeroSkill1` 等）之间没有对照表。写规则前需要先建这张表，
   否则只能记"官方会返回 16"，无法变成我们的 Action。

> 因此 C 组 16 条的正确推进顺序是：**GOT 槽位解析 → 动作码对照表 → 逐条落地**，
> 而不是"先重建函数边界"。边界这一层已确认没有问题。

## 六、防复发

- `reverse/disasm_one.py` 已改为走 PT_LOAD 映射，并新增 `--prologue` 回显入口判定。
- `scripts/test_disasm_addr.py` 固化了三条断言：VA→偏移换算、52 条地址在 VA 映射下
  落在序言（≥90%）、把地址当文件偏移时**不**落在序言（≤10%）。
  最后一条专门用于捕获"回退到裸偏移读法"这类回归。
- 方法论教训：**工具输出的地址语义必须先用一个可证伪的统计量校准**（本例 E2 vs E3 的
  100% vs 1.9%），再拿它下"代码是什么样"的结论。单点抽样会得到随机结论。
