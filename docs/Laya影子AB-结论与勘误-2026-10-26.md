## ★ 决定性发现：融合从未接入生产决策路径

`m2_agent_v2.py --laya ensemble` 看起来接上了融合，但 `main()` 里只做了
`optimizer.set_scorer(...)`；而**生产决策函数 `decide()` 从不调用 `optimizer`**
（它对 optimizer 的唯一引用是 `from wzry.decision.optimizer import enemy_hero_trusted`）。

实测（120 帧，`beta=100.0`，scorer 已启动）：

| 观测 | 结果 |
|---|---|
| `decide()` 输出变化 | **0 / 120 帧** |
| scorer `submits` | **0**（`reorder()` 一次都没被调用） |
| 同批 120 帧的生产动作分布 | skill 47 / map_move 28 / move 23 / attack 20 / restore 1 / combo 1 |

→ **`--laya` 是装饰性开关**。这也一次性解释了此前所有"翻转率 0""reorders 0"的观测：
不是模型不行、不是 β 太小、也不是基线退化，而是**打分器根本没被调用**。

静态核验已固化为 `scripts/check_laya_wiring.py`（结论 `unreachable`，`decide()` 667 行无可达标记，
`set_scorer` 仅在 `main()` 调用）。

**要让融合生效，必须先决定接入点**：在 `decide()` 的哪一步插入（威胁评估？目标选择？移动方向？），
以及"异步 scorer 的结果只能滞后一拍使用"这个语义如何与决策时序对齐。这是一次真正的设计改动，
不是调参。

## 0. 结论

1. **Laya 能跑通**：加载 ~5 s，`submits` 与 `predicts` 同步（298–300/300），0 错误、0 熔断。
2. **延迟远超预算**：e2e p50 **127–149 ms** / p95 375 ms（纯推理 117–133 ms），比 G1 的 40 ms 高 3–9 倍
   → 只能异步旁路。这条与《决策延迟基准》独立互证。
3. **本次 A/B 的基线无效**，且融合本身未接线（见上节），因此**不能用翻转率评价 Laya 或生产规则**。

## 1. 为什么基线无效（重要）

脚本沿用了 `eval_decision_offline._fallback_action()`。那个函数是**占位兜底**：
"走向己方绿点"，恒返回 `map_move`。而 `optimizer._solve_core()` 有一条 v2.73 动作白名单：

```python
if fallback_action.get("type") in ("skill", "attack", "combo", "recall", "restore", "none"):
    return fallback_action          # solve 只优化移动
```

两者叠加 → 技能/攻击/回城全部被换成 `map_move` → 基线 **100% `map_move`**。

**生产口径（直接调 `m2_agent_v2.decide`）并不是这样**：
move **87.65%** / none **8.19%** / skill **1.81%** / recall **0.41%** / restore **0.26%**。
详见 `docs/数据专题/动作分布对照-2026-10-26.md`（并发会话用 `report_action_distribution.py --prod` 实测）。

→ 所以：
- "规则退化、只会 map_move"**不成立**（技能通道是通的，只是占比低）；
- "Laya 翻转率 0" **不是 Laya 的问题**，是基线被钉死成 `map_move` 的结果。

## 4. 要做出有意义的 Laya A/B，需要三步

1. **换基线**：用 `m2_agent_v2.decide()`（生产口径）而不是 `_fallback_action()` 占位兜底；
   或以 `report_action_distribution.py --prod` 的分布作为对齐目标。
2. **换判据**：不再看"与规则的一致率"，改看 S2-3 的收益标签 / 真机胜率——否则只是拿另一个启发式当裁判。
3. **改作用点**：现在的融合只重排候选；若基线里技能只占 1.8%，重排能翻转的空间也很小。
   想让 Laya 起作用，得让它参与"移动 vs 战术"的**门控**，或直接以候选标签为动作空间做 argmax。

## 6. 勘误：`stale_probs_ttl` 真正生效后的重测（22:29）

本文 §3 表格 C 行（298 predicts / **stale_hits=2** / reorders=2）是在 `_last_probs`
写入路径落地**之前**测的——那时 `stale_probs_ttl` 只看得到空缓存，等于没开。

`_last_probs` 落地后，用**同一机制**重测（509 个规则活跃帧、2Hz、`--stale-ttl 0.5`、β=4）：

| 指标 | 数值 |
|---|---:|
| submits / predicts | 389 / 389 |
| `stale_hits` | **119** |
| `reorders` | **120**（占 submits 31%） |
| 翻转 | 仍 **0** |
| e2e p50 / p95 | 118.6 / 134.3 ms |

→ **"异步层只能救回 2 帧"不成立**，实际能救回 31%。但这不改变"翻转 0"的结论，
因为瓶颈在别处（见下节）。表格 C 的数字请按本行替换。

## 7. 即使接线修好，也还有三层限制（定量，不加载模型可复算）

脚本 `scripts/probe_laya_headroom.py`（`runs/eval/laya_headroom.json`），509 个活跃帧：

| 观测 | 数值 |
|---|---:|
| 规则 top-1 粗类 | move 503 / none 6 |
| top-2 与 top-1 同粗类 | 479 / 509 |
| top-8 内存在异粗类候选 | **491 / 509（96.5%）= k 内理论翻转上限** |
| 翻到异粗类所需原始分差 | p50 **1.82** / p90 2.595 / max 3.135 |
| `gv >= r_max` 返回 `grid_best` | **125 / 509（24.6%）** |
| β 可补极差 = β 本身；可按 β 翻转帧数 | β=1→77、β=2→305、β=4→491 |

**四层限制（层 0 由上文发现，层 1–3 本节实测）**：

| 层 | 机制 | 量级 | 后果 |
|---|---|---|---:|
| 0 接线 | `decide()` 不调用 `optimizer` | **100%** | `--laya` 完全装饰性 |
| 1 规则侧 | `_solve_core` 先算 `r_max`（原始分）再 `reorder`，之后 `if gv >= r_max: return grid_best` | 24.6% | 该分支用原始分比较，Laya 的选择被整体丢弃 |
| 2 异步侧 | 缓存键 `(状态桶, 候选标签)`，结果下一拍才能消费 | 不开 stale：可用 1/508（0.2%）；`--stale-ttl 0.5`：可用 120/389（31%） | 不开 stale 时 ensemble **一次都不重排** |
| 3 信号侧 | 需 `β·(p_异 − p_1) > gap` | gap p50=1.82；β=4 时仍需 Δp>0.455 | 模型对非规则首选没有压倒性置信度 |

→ 四层**串联**：层 0 不通时其他三层全部不可观测。修层 0 之后，层 1/2 是接线问题（可修），
层 3 才是模型能力问题。**在四层未分开前，任何 β 标定和翻转率对比都无意义。**

**证据等级**：层 1/2 的量级是逐帧实测；层 3 的「需 Δp > …」是 `gap_cross` 与 β 的算术比较，
**未逐帧确认那 120 个 reorder 帧是否恰好落在 `grid_best` 子集里**（若高度重叠，主因应归层 1）。
要闭合这个缺口，需在 `run_pass` 里同时记录 `reorder` 后的 `scored[0]` 类型与 `solve()` 最终返回类型。
