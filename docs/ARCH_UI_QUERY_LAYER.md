## 1. 为什么单独成层（问题与结论）

这类操作会**整屏遮挡**：开商店 / 战绩 / 属性面板时，主战斗感知看到的是面板而不是战场。
所以它不能是"主感知里再多几个识别函数"，而是一次**独占的模态操作**：

```
打开(点击) → 读面板 → 回填状态层 → 关闭 → 交还屏幕
```

由此本层的核心不是识别精度，而是三件事：
1. **模态锁**（同一时刻只允许一个面板占用屏幕，占用期间主决策不得出手）；
2. **卡死逃生**（无论如何都要把面板关掉，且**要验证真的关掉了**）；
3. **不猜**（未标定就降级为"不执行"，识别不出就返回空，不编数据）。

## 2. 总体分层

```
┌─ 主战斗感知（实时、连续、只读战场）──────────────────────────────┐
│ 帧采集 1280×720（16:9）/ 1280×576（20:9） · YOLO 单位框(13类) · 小地图/圆点 · 自身血条蓝条     │
│ 头顶血条(敌/友比例) · 顶部头像条 · 技能就绪(变暗) · 阵亡/击杀横幅    │
└───────────────────────────┬──────────────────────────────────────┘
                            │ 观测
┌─ 辅助 UI 感知（条件性出现、整屏遮挡、模态独占）───────────────────┐
│ 面板识别(亮卡片 / 深蓝暗遮罩) · 面板内数字读数 · 顶部锁定目标条      │
│ 切法：点击=执行层的 UI 触发动作 / 面板=辅助感知 / 内容=回填状态层    │
└───────────────────────────┬──────────────────────────────────────┘
                            │ 回填（走白名单字段，不另开数据通道）
┌─ 状态汇总层 GameState ─────┴─────────────────────────────────────┐
│ ui / dets / minimap / self / extra（统一 schema；未标定 -> 缺省 -1）│
└───────┬──────────────────────────────────────┬──────────────────┘
        │ 写事件                               │ 读状态
┌─ 记忆层 EventLog ─────────────┐   ┌─ 规则 / 决策区 ──────────────┐
│ 事件流 jsonl · 冷却估计        │   │ 支线：加点 / 出装 / 资源点 /   │
│ 轨迹→朝向 · 面板读数入记忆     │   │       风险门控               │
│                               │   │ 策略：off | shadow | bc      │
└───────────────────────────────┘   └───────────┬──────────────────┘
                                                │ 动作
                                 ┌─ 执行区 ─────┴─────────────────┐
                                 │ adb tap/swipe（坐标自动换算）   │
                                 │ 动作队列（深度 ≤1，不过期）      │
                                 └───────────────────────────────┘
```

**各层"不做什么"**（避免职责混杂）：
- 主战斗感知**不点屏幕**、不读面板；
- UI 查询层**不自己造输入通道**（复用执行区的 tap）、**不另开数据通道**（回填走统一字段名）；
- 决策区**不看像素**，只读状态层与记忆层；
- 记忆层**不做决策**，只记"发生了什么 + 置信度"。

## 3. UI 导航 / 信息查询层

实现：`wzry/uiquery/panel.py`（`PanelNavigator`）。

### 3.1 流程与不变量

| 步骤 | 行为 | 不变量 |
|---|---|---|
| acquire | 检查模态锁 + 面板名合法 + `ui_taps[panel]` 已标定 | 三者任一不满足 → 拒绝，**一个点击都不发** |
| 开工检查 | 先 grab 一帧，若屏幕已被面板占用 → 拒绝 | 避免把"屏幕上本来就有的面板"误判成"我刚打开成功" |
| 打开 | 下发 `ui_taps[panel]` 的 tap | 点击只走执行区的 tap |
| 轮询 | 在 `timeout` 内等 `is_panel_open(frame)` | 超时 → 走逃生 |
| 落定 | `time.sleep(settle=0.35)` 后再取帧 | 打开动画期间读到的可能是过渡帧、✕ 还没就位 |
| 读 | `read(panel, frame)` → 统一字段 dict | 只回填白名单字段 |
| 关闭 | `_close_and_verify()`：点 `ui_taps.close`，**回帧验证**，关不掉重试 1 次 | `closed` 只反映"验证过确实关了" |
| release | 无论成功失败都释放模态锁 | `busy` 期间主链路不得出手 |

`run()` 返回：`{"ok","reason","data","opened","closed"}`。
关不掉时 `reason` 会追加 `⚠ 关闭未确认：面板可能还挡着屏幕，主链路不得出手`。

### 3.2 接口

```python
PanelNavigator(tap=None, taps=None, timeout=3.0, panel_thr=0.18, settle=0.35)
  .busy                     # 模态锁是否被占用（主决策据此停手）
  .acquire(panel)           # -> (ok, reason)
  .release(reason="")       # 交还屏幕
  .read(panel, frame)       # -> {field: value}，未标定 -> {}
  .run(panel, grab, tap=None, reader=None)
```

`PANELS = ("scoreboard", "hero_panel", "shop", "skill_info")`。

### 3.3 关闭验证（这一条是踩出来的）

真机实测：**点完 ✕ 面板还开着**（结构分仍 1.27），而 `run()` 原来在 `finally` 里直接
`res["closed"] = True` —— 那是"我点过了"，不是"关掉了"。主链路据此以为屏幕已交还，
接下来会对着面板下发战斗动作。现在改为：点 → `settle` → 回帧判 `is_panel_open` → 未关则重试 1 次 →
仍关不掉则 `closed=False` 并告警。另外**没有标定 `close` 时直接返回 `closed=False`**（不自欺）。

### 3.4 开工闸门

屏幕上已经有全屏 UI（上一轮没关掉的、或玩家自己开着设置菜单）时，轮询会**立刻误判"我刚打开成功"**，
然后去读一个根本不对的面板 —— 真机撞到过（设置菜单同样是深蓝遮罩，结构分也 ≥1.0）。
现在开工前先判一次，占用就拒绝执行，且**不下发任何点击**。

## 4. 面板识别判据（两种结构，各一条）

单条"中央亮卡片"判据**不够**：战绩面板不是亮卡片。

### 4.1 亮卡片 `panel_open_score(frame)`
`= (中央 22%~78% 区均值 − 四周 12% 边带均值) / 255`，阈值 `BOARD_BRIGHT_THR = 0.18`。
适用：商店 / 英雄属性 / 结算类（中央亮、四周暗遮罩）。

### 4.2 深蓝暗遮罩 `scoreboard_open_score(frame)`
`= 中央区深蓝像素占比`（H∈[95,135]、S≥60），另有**亮度门** `mean ≤ BOARD_MEAN_MAX = 85`
（不满足直接返回 0）。阈值 `BOARD_BLUE_MIN = 0.62`。
为什么必须单独一条：战绩面板是**深蓝暗遮罩**，中央比战场还暗（实测 center−border = **+3.3**，
即 `panel_open_score ≈ 0.013`，而战场是 **+18 ≈ 0.07**）→ 亮卡片判据对它的读数几乎为 0，
远低于 0.18 阈值，等于完全看不见它。

### 4.3 归一化 `panel_open_norm(frame)`
`= max(panel_open_score/0.18, scoreboard_open_score/0.62)`，**≥1.0 即"面板打开"**。
两种面板量纲不同，归一化后扫描式标定（`probe_ui_tap`）才能共用同一套"跳变"判定。

### 4.4 实测分离度（真机帧）

| 画面 | 亮卡片 | 战绩深蓝 | 归一化 | 判定 |
|---|---|---|---|---|
| 战绩面板打开 | 0.013 | **0.815** | **1.31** | 打开 ✅ |
| 对局中（无面板） | 0.045~0.077 | 0.000 | 0.39 | 未打开 |
| 结算页（失败横幅） | 0.121 | 0.004 | 0.67 | 未打开 |
| 结算页（横幅入场动画中） | **0.186** | 0.004 | **1.03** | ⚠️ **假阳** |
| 加载 VS 页 | 0.129 | 0.524（mean 93.7 → 被亮度门挡） | 0.72 | 未打开 |
| 阵亡暗屏 | 0.096 | 0.431 | 0.69 | 未打开 |
| 设置菜单打开 | — | ~0.97 | ≥1.0 | 判为"屏幕被占用" ✅ |

> ⚠️ 上表倒数第二行那格是**已知弱点**：亮卡片阈值 0.18 离结算页太近（同一结算页随动画在
> 0.67~1.03 之间抖）。方向是安全的（宁可拒绝也不乱动），但收紧需要**真实商店/属性面板帧**做基准。

## 5. 寄存器与标定体系

### 5.1 坐标空间
标定逻辑空间统一为 **1280×720**；采集端 `ScreencapCapture` 保持宽高比、长边缩到 1280（20:9 → **1280×576**，16:9 → 1280×720），不再无条件拉伸到 720。
执行区 `AdbExecutor.tap` 内部按"最近一次读到的设备显示尺寸"线性换算到设备像素，故配置里只写帧空间坐标。

### 5.2 当前寄存器（`configs/calibration_absolute.json`）

```jsonc
"ui_taps": {
  "scoreboard": [862, 28],   // 打开键＝对局时间/比分那一块（不是 toggle！）
  "close":      [1218, 93]   // 战绩面板右上角 ✕
},
"panel_rois": {
  "scoreboard": {
    "ally_kills":  [604, 82, 658, 112],   // 中间 "N vs N" 的左数（我方人头）
    "enemy_kills": [686, 82, 744, 112],   // 中间 "N vs N" 的右数（敌方人头）
    "ally_gold":   [536, 84, 606, 112],   // 我方队伍总经济 "XX.Yk"
    "enemy_gold":  [766, 84, 830, 112]    // 敌方队伍总经济
  }
},
"lock_target": { "x0": 578, "x1": 764, "y0": 14, "y1": 31 }  // 顶部锁定目标条的"条体"
```

几条容易踩的语义/边界：
- 打开键**不是 toggle**：面板开着时再点 (862,28)，结构分仍是 1.26 → 必须用 `close` 的 ✕。
- 表头语义：左半边是 `[龙]N [兵]N [$]经济`，**中间的 `N vs N` 才是人头比分**（不是图标旁那两个数）。
- kills 框按"蓝方右对齐 / 红方左对齐"定（两帧不同位数反推），1 位与 2 位数都能读。
- gold 框要**避开币图标**：我方币标 504–524、敌方币标 745–764 → 框左界取 536 / 766。

### 5.3 scan-tap：为什么"反着做"标定

面板按钮是**对局 HUD 的绝对坐标**，标定它的本质就是"试点 + 看反馈"。监听式取证要求
"人正好点开面板"，太被动（实测卡在结算页四分钟）。所以让脚本自己点：
`scripts/probe_ui_tap.py` 对每个候选点比较**点击前/后**的结构分。

判定（`judge_tap`，纯函数，可离线单测）：

| 条件 | verdict |
|---|---|
| `s1 ≥ 1.0` 且 `Δs ≥ 0.5` | `panel` → 判定为面板按钮（**以结构分为准**） |
| 结构分没动但 `diff ≥ max(18, 2×闲置抖动)` | `changed`（只当线索，存证待人工判） |
| 其他 | `none` |

为什么以结构分为准：**对局里镜头一划 diff 就能到 53（闲置抖动才 0.4）**，只看 diff 必然误报；
结构分是瞬时的、与镜头无关（实测对局帧 0.28~0.43，面板帧 ~1.3）。

四道安全闸（默认全收紧）：

| 参数 | 作用 | 未加时 |
|---|---|---|
| `--confirm-in-battle` | 确认在对局内 | 只拍基线帧就退出（`return 5`），**不下发任何点击** |
| 开工前占用检查 | 基线帧已是面板 → 拒绝 | `return 6`，不产生垃圾结论 |
| `--write` | 才落盘 configs | 默认干跑（只打印 + 存图） |
| 关闭验证 | 开成功后再关回去（先试同点，再试 `--close-points` 给的关闭键） | 关不掉则标记"可疑"，拒绝写盘 |

> 不做"自动判断是否在对局"：试过 `minimap.find_minimap` 当判据 —— 它在**真实对局帧**上
> `found=False`、却在**选英雄页** `found=True`。判错更危险，所以这里不做伪检测，交给人拍板。

返回码：`0` 成功 / `2` 没有候选点打开面板 / `3` 取不到帧 / `4` 能打开但关不掉（或没关闭点）/ `5` 保护模式 / `6` 开工前屏幕已被占用。

### 5.4 两个辅助取证脚本

| 脚本 | 用途 | 特点 |
|---|---|---|
| `scripts/grab_panel.py` | **监听式**取面板帧（人工点开、脚本抓屏，`--mode diff\|panel`） | 抓突变帧 + 面板内数字块清单 |
| `scripts/watch_enemy.py` | **敌人露头**取证（只读，不发点击） | 检测到 enemy_hero 即落盘帧 + 顶部条带，打印 camp_src 与红条比例 |

`watch_enemy.py` 的存在理由：两项卡住的感知（敌方血量比例、顶部锁定目标）**只在敌人可见时才有数据**，
缺的从来不是算法而是素材。

## 6. 字段与命名约定

`PanelNavigator.read()` 只回填**白名单**字段（`ALLOWED_FIELDS`）：

```
gold, level, kills, deaths, assists, skill_point,
enemy_items, enemy_level, hero_items, hero_attrs,
ally_gold, enemy_gold, ally_kills, enemy_kills
```

**为什么队伍级数据不复用 `gold` / `kills`**：主链路里 `gold`/`kills` 是**英雄自己**的口径
（HUD 读数 / 击杀横幅）。把"队伍总经济""队伍总人头"塞进同名字段，会让状态层在两套口径间跳变。
故一律用 `ally_*` / `enemy_*` 显式命名。

**`K_GOLD_FIELDS = ("ally_gold","enemy_gold")`**：面板经济写成 `XX.Yk`（一位小数 + 千后缀），
必须走专用解析 `digit_reader.read_k_gold()`
（做法：逐字符块读、**丢掉低置信字符**，因为 `k` 被误认成 8 时置信度只有 ~0.19，而真数字稳定 0.85~0.97；
面板固定一位小数 ⇒ `int(数字串) × 100`）。

> 对照：`read_number("33.7k")` → **3378**（丢掉小数点 + 把 k 当数字），差两个数量级。直接用会毒化状态层。

## 7. 感知读数清单（v15.x 已落地）

| 读数 | 实现 | 状态 |
|---|---|---|
| 敌方血量比例（场景头顶红条） | `wzry/vision/hero_hp.py`（`enemy_hp_ratio` / `enemy_hp_from_dets`） | 真机团战已验证；**有 HUD 假阳问题**（见 §10） |
| 我方/友方血量比例（顶部头像条） | `wzry/vision/top_status_bars.py` + `top_bar` 寄存器 | `top_bar` 已标定（5 槽，ally_only）并被 m2 消费；见 `extra.top_bars` |
| HUD 数字（等级/金币/技能点/剩余 CD） | `wzry/vision/digit_reader.py`（模板匹配，`digit_rois`） | `digit_rois` 仅有 gold / item_price；等级/技能点/CD 尚未标定 |
| 面板数字（队伍人头/经济） | `panel_rois` + `read_k_gold` | 已标定 + 三层验证 ✅ |
| 顶部锁定目标条（选中 / 正在攻击敌方英雄时才出现） | `hero_hp.lock_target()` + `lock_target` 寄存器 | **已落地并接进 m2 状态层**：19 帧（8 有 / 11 无）全判对；填充比例与条内文字真值误差 ≤0.7pp ✅ |
| 技能就绪/变暗、阵亡/击杀横幅 | `hok_yolov5` 探针 + 二值化 | 已落地 |
| 资源点拆分（暴君/野怪独立类） | 13 类表 | 已落地（真机出现 3 次） |

**状态层键约定（m2）**：
- `ui.lock_target`（bool）**每拍都写**；`ui.lock_target_hp`（比例）**只在有锁定目标时写** ——
  缺失 ≠ 残血，用它的人必须先看 `ui.lock_target`（不许拿上一拍的残血值当现在）。
- 这两个键放在**每拍区**、不跟附近那圈 0.5s 节流：读数只扫 187×17 的小条，开销可忽略，
  而"有没有锁定目标"必须每拍都新。
- 两个键**暂未进 `encoding.UI_KEYS`**：那会改 `UI_DIM`，让已训练的 BCNet 权重对不上，要加得先重训。
- **消费点（v15.4，都只在规则层、都只放宽接战门槛、都不改移动目标）**：
  ① **收人头窗口**：`ui.lock_target_hp ≤ KILL_HP_MAX(0.30)` 且自己 `≥ KILL_SELF_HP_MIN(0.35)`
     ⇒ 接战门槛 `0.60 → 0.35`（reason `kill_confirm_attack`，触发打印 `[kill]`）；
  ② **占优推进**：`extra.enemy_hp_scene` 里 `≤ PRESS_ENEMY_HP_MAX(0.35)` 的敌人 **≥2 个**
     且自己 `≥ PRESS_SELF_HP_MIN(0.50)` ⇒ 接战门槛 `0.60 → 0.50`（reason `press_advantage_attack`，打印 `[press]`）。
     ② 的读数在 0.5s 节流块里、被跳过的拍会缺失，故用**有界缓存**（`n_low_enemies` + `n_low_t`，
     `PRESS_STALE_S=0.6s` 内沿用）—— 否则许可每拍闪断，英雄会走一步撤一步。
  未消费方：BCNet（两个键都不在 `UI_KEYS` ⇒ **规则层能立刻用、策略层看不到**）。

`hero_hp.enemy_hp_ratio` 的口径与要点：
- `ratio = 实心红条长度 / 满条宽`，`FULL_BAR_PX = 115`（与 `self_bars` 同源，1280 帧空间）。
- **扫描带宽必须 ≥ 满条宽**：`scan_w = max(框宽×0.70, 满条宽×1.15)`。若沿用"框宽×0.70"，
  框只有 60~90px 时会**系统性低估**。
- 相机距离会改变屏幕上的像素长度（远小近大）→ 只当"相对血量/是否残血"特征，**不是精确血量**。
- `camp_src == "default"` 的幻影框不参与统计。

## 8. 记忆层

## 11. 真机教训清单（踩坑 → 现行做法）

| 踩到的坑 | 现象 | 现行做法 |
|---|---|---|
| `wait_frame` 无新帧时返回**同一缓存对象** | 按对象比对 diff 恒为 0；按"重试 6 次"去重又比采集间隔短 → 误报"取不到帧" | 按**对象身份**去重 + 按**时间预算**等新帧 |
| 面板打开动画未落定 | 刚检测到打开就点 ✕ 点不中、读到过渡帧 | `settle=0.35s` 后再读/关 |
| `finally` 里硬写 `closed=True` | 面板还开着，主链路以为屏幕已交回 | 回帧**验证**关闭 + 重试 + 未确认告警 |
| 深蓝暗遮罩面板 | 亮卡片判据给它负分 → 以为"没打开"，逃生"关一次"反而把面板留住 | 新增深蓝占比判据 + 亮度门 + 归一化 |
| 上一轮面板没关掉 | 下一轮全部候选点都在面板上点 → 全"无反应"，白跑一轮 | 开工前占用检查，占用即拒绝 |
| 对局镜头移动 | diff 冲到 53 被当成"打开面板" | 判定**以结构分为准**；diff 只做兜底，且先量**闲置抖动** |
| 单帧读像素定位按钮 | 同一个图标在两帧读出相差 40~100px，据此写死坐标会点空 | 改用 **scan-tap**：候选点 + 点击反馈定音，坐标以"点得开"为准 |
| 面板经济 `XX.Yk` | `read_number` 读成 3378（丢小数点 + k 当数字） | 专用 `read_k_gold`：低置信字符过滤 + ×100 |
| `numpy` 数组当条件 | `frame = grab() or old` 抛"truth value ambiguous" | 显式 `if _nf is not None` |
| **注释与代码被挤在同一行**（历史格式损坏，形如 `# 底部信息条    beh_label = …`） | 赋值从没执行 → `NameError` 被下游 `except: pass` 吞掉 → `temp/live_annot/behavior.jsonl` **从来没生成过**（`self_reflect.py` 也在读它 → 一直在读空气） | 修好该行；**写盘失败的 `except` 不再静默**，改为打印 `[annot-record] …`。排查这类"看起来在跑、其实没产出"的坑，第一步就是**先确认产物文件真的存在** |
| `ScreencapCapture` 的 `serial` 默认写死 `127.0.0.1:16384`，而 m2 构造它时**没把 `--serial` 传进去**（scrcpy 分支传了） | 换到真机（USB `9f352c1f`）走 `--capture screencap` 时**恒连模拟器** → `0 帧`，但日志只写"完成: 0帧"，看不出原因 | 与 scrcpy 分支对齐传 `serial=getattr(args,"serial",None)`；传 `None` 时行为与以前完全一致 |
