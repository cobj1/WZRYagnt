# 离线对局开局 Runbook

Agent 自行进入「离线5V5 / 单人训练」对局的固定步骤。2026-10-20 在 MuMu 模拟器上按用户演示走通（小乔，进入对局 00:16）。

- 环境：MuMu 15，横屏 1920×1080，adb `127.0.0.1:16384`，包名 `com.tencent.tmgp.sgame`
- 参考截图：`docs/assets/offline_match/01~06*.png`（实际为约 0.38 倍缩略图，仅作界面判据；点击坐标按 1920×1080）

## 前置

```bash
cd D:/work/aiKings/WZRYagnt
./tools/scrcpy/adb.exe connect 127.0.0.1:16384
./tools/scrcpy/adb.exe devices          # 应为 127.0.0.1:16384  device
```

游戏未启动时：

```bash
./tools/scrcpy/adb.exe shell monkey -p com.tencent.tmgp.sgame -c android.intent.category.LAUNCHER 1
```

等主界面出现（右侧竖排图标、底部「开始游戏」）。每一步先截图确认界面，再点下一步：

```bash
./tools/scrcpy/adb.exe exec-out screencap -p > temp/mumu_check.png
```

## 读内存前的离线门禁（2026-10-26 起强制）

`MemSource.connect()` 现在要求离线会话 token，没有 token 直接拒绝读取：

```bash
# 进入离线对局后（需带 cv2 的 venv）
venv/Scripts/python.exe run_offline.py verify        # 交互确认 + 自动校验
venv/Scripts/python.exe run_offline.py verify --yes  # 跳过人工确认
venv/Scripts/python.exe run_offline.py status        # 查看 token 是否有效
venv/Scripts/python.exe run_offline.py revoke        # 立即作废
```

校验方式：打开对局内设置 → 检测顶部黄字「当前处于单人训练相关模式中…游戏已暂停」
（离线实测约 536 黄色像素@1280 宽，在线同位置为 0）+ 隔 2.5s 时钟冻结 → 通过后写
`runtime/offline_session.json`（pid/serial/**45 分钟单局有效期**）。校验只截图和点击，不读内存。

- 新开一局、游戏重启或 pid 变化后需重新 `verify`；token 过期同样重签。
- 离线 UI 异常时可用 `verify --manual`（跳过自动检查，仍要人工确认，method 记为 manual）。
- 回归：`python scripts/test_offline_gate.py`（无设备）。

## 注意与坑

- **「再来一局」有两种落点（2026-10-26 实测）**：自然失败结算后点它，会**直接进入 VS 载入并开局**
  （不经过选英雄房间，阵容沿用上一局）；从「退出本局」判负后点它，才回到选英雄房间。
  以截图为准，别盲点「下一步」。
- **MuMu 窗口失焦会让局内对局暂停**（设置面板自动弹出、顶部时钟冻结），此时摇杆推不动、
  复活倒计时也不走。跑自动送塔/复活实验前先把 MuMu 置前台（computer-use `activate_window`），
  或保证实验期间窗口有焦点；否则脚本会触发"连续 5 次无位移"保护并转为被动采样（2026-10-26 实测）。
- **2026-10-26 14:43 复验**：最终失败结算页点「再来一局」回到了选英雄房间（不是直接进 VS），
  与上一条"自然失败直接开局"的描述不同，判断可能取决于是否已出最终结算页；以截图为准。
- **离线训练的阵容强制全局唯一**：10 个槽位英雄互不重复，AI 不会选玩家已选的英雄。
  2026-10-26 共采样 19 局（玩家英雄分别取 小乔/艾琳/妲己），每局 10 个 cid 全不同、
  0 次镜像 —— 因此该模式**拿不到「同英雄双阵营」样本**（详见 `reverse/out/mem/ACTOR_FINDINGS.md` §18）。
- 不要点设置弹窗中下方的「退出本局」——会判负结束本局（想快速换局时才故意用它，见上表）。
- 局内高负载下 `adb exec-out screencap` 可能卡住（adbd wedge，历史问题）；采集画面优先走 scrcpy 流，开局阶段截屏没问题。
- 模拟器重启后 adb 需重新 `connect`；端口 16384。
- **MuMu 重启后 root 会掉**（`su` 不存在、`root_permission` 设置对 CLI 启动无效）：
  读内存前先 `adb -s 127.0.0.1:16384 root`，否则 `/proc/<pid>/mem` 读不出来（表现为 actor 表 0 单元）。
- 主界面若弹活动/公告，先关弹窗再点「离线5V5」。
- 坐标基于 1920×1080；分辨率或 UI 版本变化时按比例缩放，并以当场截图为准。
